# W5 设计笔记

## 一、拆解需求练习

**需求**：系统要能回答公司政策问题、查文档统计、算数，与公司无关的问题正常聊天。

**拆解结果：系统处理四类问题**

| 问题类型 | 例子 | 走什么路径 | 用哪个工具 |
|---|---|---|---|
| 公司制度政策（答案在文档里） | "请假流程？" | 检索 | search_kb |
| 数据统计（答案在数据库表里） | "一共几个文档？" | 查库 | query_documents_db |
| 数学计算 | "2000×3？" | 计算 | calculator |
| 普通对话 | "你好" | 直接回答 | 无 |

**判断逻辑**：LLM 读取每个工具的 description（描述），判断"这个问题的答案在哪里"，选择匹配的工具；如果哪个工具都不需要，就直接生成回答。（代码里 tool_choice="auto" 让 LLM 自主决定）

**边界处理**：如果用户问的知识库里没有（如"公司有几个部门"），search_kb 返回空结果，Agent 应如实回答"知识库中未找到相关信息"，绝不编造——这是 RAG 防幻觉的关键闭环。

## 二、多步任务调试记录（重要发现）

**现象**：问"alice 有几个文档？平均每份多少 chunk？"时：
- 第一次运行：Agent 超过 6 轮循环，返回"任务可能未完成"
- 原因分析：该问题需要多步操作（查 alice 文档 → 查各文档 chunk 数 → 计算平均），LLM 多步推理时可能绕圈或步骤多，6 轮不够
- 解决：把最大轮数从 6 加大到 10（填你改的数字）
- 第二次运行：成功，Agent 查出 alice 有 3 个文档（第一章 3 chunk、第二章 3 chunk、完整版 8 chunk），平均 ≈4.67 chunk

**经验教训**：
1. Agent 多步任务可能超过轮数上限，加大轮数可以提高成功率，但会增加 API 调用次数（更慢更贵）
2. 轮数上限是"安全阀"——防止 Agent 死循环无限烧钱，不能无限加大
3. 更优的解法是让工具描述更清晰、让 Agent 少走弯路，而不是单纯加轮数
